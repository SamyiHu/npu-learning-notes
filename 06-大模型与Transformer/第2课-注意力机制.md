## 一、核心一句话

**大模型的任务 = 预测下一个词。注意力 = 每个词"看"所有其他词，按相关度吸收上下文。**
底层全部落在：**点积 + softmax + 加权求和**——仍是"乘加 + 掰弯"家族。

## 二、为什么 CNN 不够，必须要有注意力

```
"小明走进教室，他把书包放在桌上，然后……"
问: "他"指谁？ → 小明（在 20 个词之前）
```

CNN 的核只看旁边 9 个像素，**天生看不见远处**。而语言恰恰是"远处的词决定意思"。所以需要一种机制：**让每个词能"看"到句子里的所有其他词** —— 这就是注意力。

对比记忆：

| | CNN 卷积 | 自注意力 |
|---|---|---|
| 视野 | 局部（3×3） | 全局（整段） |
| 关系 | 空间邻近 | 语义相关（可隔任意远） |
| 权重 | 核参数共享 | 每对词一个动态权重（由内容算出） |

注意：注意力的"权重"**不是**训练后固定的一张表，而是**每句话现算的**——这点和卷积核很不一样，也是它贵的原因之一。

## 三、注意力 = 查资料（Q / K / V）

```
你脑子里的问题 = Query（Q，你要找什么）
每本书的标题   = Key（K，这本书是什么）
书的内容       = Value（V，这本书讲了什么）
```

流程：拿 **Q** 和每本书的 **K** 比对"像不像" → 像的权重高 → 按权重把 **V** 加权汇总。

**自注意力**：把这套用到词身上，**每个词都当一次"查资料的人"，去"看"句子里的所有其他词。**

### 真实模型里 Q/K/V 从哪来

教学例子常假装 Q=K=V=词向量本身。真实 Transformer 里，每个词的向量会先乘三个**学出来的矩阵**：

```
q = Wq · x     k = Wk · x     v = Wv · x
```

- Wq / Wk / Wv 是训练得到的权重（推理时固定 → 可以量化进 NPU）
- 所以"同一句话"在不同层、不同头里，会投影出不同的 Q/K/V

## 四、四步走（带手算：我 爱 猫）

词先变成数字（embedding，此处用二维）：

```
我 = [1, 0]
爱 = [1, 1]
猫 = [0, 1]
```

（真实模型里 Q/K/V 是三个学出来的变换，此处为讲直觉假装 Q=K=V=词本身。）

**第1步**：拿"爱"的 Q 去和每个词的 K 做**点积**算相关度：

```
相关度(爱, 我) = [1,1]·[1,0] = 1
相关度(爱, 爱) = [1,1]·[1,1] = 2
相关度(爱, 猫) = [1,1]·[0,1] = 1
```

**第2步**：分数转成"加起来=1"的权重——**Softmax**：

```
原始分 s = [1, 2, 1]
softmax: e^s 再归一化
e^1≈2.72, e^2≈7.39, e^1≈2.72  →  总和≈12.83
权重 ≈ [0.21, 0.58, 0.21]     ← "爱"和"爱"最像，权重最高
```

Softmax 做两件事：

1. **保持序**：分高 → 权重大  
2. **变成概率**：非负、加起来 = 1，才能当"取多少 V"的系数  

> 温度 T 很大 → 权重更均匀（多听各方意见）；T 很小 → 几乎只听最高分。原理剧场 P4 可拖。

**第3步**：按权重把所有词的 V 加权平均：

```
"爱"的新表示 = 0.21×[1,0] + 0.58×[1,1] + 0.21×[0,1] = [0.79, 0.79]
```

**第4步**：每个词都做一遍同样的事（并行）。

**"爱"原来的表示 [1,1] 变成了 [0.79, 0.79]——里面混进了"我"和"猫"的信息。这就是"词理解了上下文"。**

## 五、写成矩阵：NPU 最喜欢的形状

把 N 个词的向量堆成矩阵 X（形状 d×N 或 N×d，按框架惯例）：

```
S = Q · Kᵀ          // 相关度矩阵 N×N
A = softmax(S)      // 按行归一化
Y = A · V           // 加权，得到新的 N 个表示
```

三步全是**矩阵乘 + 逐元素非线性/归一化**。

| 形状直觉 | 含义 | 硬件 |
|---|---|---|
| N×N | 每个词对每个词一个分 | N 翻倍 → 元素×4 |
| 多头 | 上述过程并行做 H 遍再拼接 | 多组 GEMM |
| 批量句子 | 再多一个 batch 维 | 还是 GEMM |

**所以注意力"贵"在 N² 存储与计算，但"好算"在极度规整——MAC 阵列吃得下。**

## 六、三个老朋友

1. **点积 = 相关度**：第1.5课说过"点积 = 默契度"，注意力用的就是它
2. **加权平均 = 乘加**：注意力本质 = 一堆矩阵乘法（Q×Kᵀ 算相关度，再 ×V 加权）。底层还是"乘加 + 掰弯"
3. **所有词同时算 = 并行**：每个词的注意力互相独立 → 正好是矩阵乘法 → NPU 最喜欢的形状

## 七、为什么"看很远"、为什么"贵"

- **看得远**：相关度是"每个词 × 每个词"，**跟距离无关**。隔 20 个词和隔 1 个词算法一样 → "他"能认出 20 词前的"小明"
- **贵（N²）**：N 个词要算 N×N 次相关度。**上下文翻倍，算力翻 4 倍**（平方增长，不是指数）。这就是长上下文贵的根本原因

```
上下文 1000 词 → 1000×1000 = 100 万次
上下文 2000 词 → 2000×2000 = 400 万次   ← 词翻倍，算力 4 倍
```

工程上还要再记一笔：**A = softmax(S) 这张 N×N 表也要占内存**。  
N=4k 时，仅一张 FP16 注意力图就是 4k×4k×2B ≈ 32MB/层/头——长上下文必须上稀疏/滑窗/FlashAttention 一类近似。

NPU 跑大模型，头号要优化的就是 N² 这一块（KV 缓存、稀疏注意力……）。

## 八、KV 缓存直觉（为第 3 课和板端实验铺垫）

生成时的循环是：

```
已有上下文 t0…tk  →  预测 tk+1  →  拼上 tk+1  →  再预测 tk+2 …
```

若每步都把历史所有词的 K、V 重算一遍，浪费巨大。  
**缓存策略**：历史 token 的 K、V 存起来；新 token 只算自己的 Q/K/V，再和缓存拼接。

```
新一步计算量 ≈ O(N) 而不是重新 O(N²) 全算
代价       ≈ 显存里要一直躺着 (K,V) 缓存
```

这就是"上下文越长，越吃内存"的来源，也是 rknn-llm / 端侧 LLM 文档里反复出现 KV Cache 的原因。

## 九、口诀

- Q 是问题，K 是标题，V 是内容
- 点积比像不像，softmax 变权重，加权汇总 V
- 矩阵三步：QKᵀ → softmax → AV
- N² 是次数不是指数；KV 缓存用空间换时间
