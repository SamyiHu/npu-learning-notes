> 阶段：06-大模型与Transformer

## 一、核心一句话

**注意力分不清顺序 → 加"位置标签"解决。完整的 Transformer 块 = 自注意力 + 残差 + 归一化 + MLP，重复 N 次。**

## 二、注意力的"坑"：分不清顺序

相关度只在乎"有哪些词、像不像"，**完全不在乎先后顺序**。

```
猫 追 狗     →  猫[1,0] 追[0,1] 狗[1,1]
狗 追 猫     →  狗[1,1] 追[0,1] 猫[1,0]
```

**两个句子的输入是完全一样的三个数字，只是顺序不同。** 注意力算出来的相关度也一模一样 → 模型把"猫追狗"和"狗追猫"当成同一个东西。这叫**词袋陷阱**：只看到有哪些词，看不到顺序，等于没看懂语言。

## 三、补洞：位置编码（Positional Encoding）

**让每个词知道"自己在第几个位置"。** 给每个位置配一个独一无二的标签，**加到词的表示上**：

```
词的数字      +   位置标签     =   词的新表示
[1, 0]            [1, 1]           [2, 1]
（猫的内容）   （"我在第0位"）   （猫 + 位置）

同一个"猫"：
  在第0位: [1,0] + [1,1]  = [2,1]
  在第2位: [1,0] + [-1,1] = [0,1]     ← 数字不同了！
```

于是：

```
猫追狗 → 猫[2,1] 追[1,0] 狗[0,2]
狗追猫 → 狗[2,2] 追[1,0] 猫[0,1]     ← 两个句子终于不一样了
```

模型从此能区分"谁在前谁在后"。

### 位置编码的三代（认脸即可）

| 类型 | 思路 | 备注 |
|---|---|---|
| 正弦/余弦固定 | 不同频率的波形当"尺子" | 原始 Transformer |
| 可学习位置 | 当参数一起训 | 简单，长度上限固定 |
| **RoPE** | 把位置"旋进" Q/K 的相对关系 | 现代开源 LLM 常见 |

**本质都一样：把"位置"混进词的表示里。**  
对硬件：加法、查表或旋转（两次乘加），几乎不改变 MAC 阵列的主负载。

## 四、多头注意力（Multi-Head Attention）

**一个 Q/K/V 组 = 一个"看问题的角度"。** 一句话里同时有好几种关系：

```
"小明看到一只猫，他决定追它。"
  · "他"指代谁？        → 指代关系
  · 谁是主语、谁是宾语？ → 语法关系
  · 语气是什么？        → 语气
```

一个头只能盯一种关系 → 放**多个头**，每头自己一套 Q/K/V，各抓一种，最后拼起来。

> 类比：一组人开会，有人盯逻辑、有人盯情绪，最后综合意见。

工程上常见做法：**总维数不变，切成 H 份**。  
例如 d_model=4096、H=32 → 每头 128 维。这样多头不把参数量炸上天。

对硬件友好：**多头 = 多组矩阵乘法，天然并行。**

## 五、完整的 Transformer 块（基本单元）

```
输入
 ↓
[自注意力] ──→ 结果 ─┐
                      │ ← 残差连接：结果 + 原输入
 ↓                  │
[归一化 LN]          │
 ↓
[MLP] ──────→ 结果 ─┼─
                      │ ← 残差连接：结果 + 原输入
 ↓                  │
[归一化 LN]          │
 ↓
 输出 → 下一块

（这个块重复 N 次，就是模型的"深度"）

> 注意：上图是原始 Transformer 的 **Post-LN** 排法（子层 → 残差相加 → LN）。LLaMA/Qwen 等现代 LLM 多用 **Pre-LN**：先 LN 再进子层，残差直接加在子层输入上；读模型图时先看 LN 在子层前还是后。
```

两个新零件：

### 残差连接（Residual）

```
y = x + F(x)
```

像改作文留原稿：F 只负责"改动量"，原文 x 一直有直达通道。

- 防止信息一层层"传丢"
- 梯度/信号有捷径 → 几百层也能训得动（ResNet 与 Transformer 共用的神来之笔）
- 推理时：就是一次 **逐元素加法**，硬件极便宜；但会占一条额外的数据通路（03 课"少搬一趟"要考虑这条支路）

### 归一化（LN）

即之前学的归一化思想；Transformer 里常用 **LayerNorm**（对单个 token 的整条特征维做标准化），不是 BN 那种跨 batch。

```
x̂ = (x - μ) / σ     再乘 γ 加 β
```

和 BN 不同：BN 的 μ/σ 是训练时统计好的常数，可以折进上一层权重；**LN 的 μ/σ 要按当前 token 的特征现场统计，不能提前折叠**。γ/β 虽是常数，也只能折进后续缩放/平移，LN 本身仍是芯片上的真实归一化单元（01 第 3 课已对比过这一点）。

### MLP：块里的"大胖矩阵"

```
MLP(x) = W2 · act(W1 · x)     // act 多为 GELU/SiLU
```

典型形状（LLaMA 类）：

```
d_model = 4096
hidden  ≈ 11008  （常常约 2.7× 上）
```

**一层 MLP 的参数量经常超过同层注意力**——它就是两块超大 GEMM + 非线性。  
对 NPU：这是和卷积一样"最好吃"的部分；量化收益也最大。

**对比 CNN 一句话：CNN 的基本单元 = [卷积 + 激活]（处理局部）；Transformer 的基本单元 = [自注意力 + MLP]（处理全局关联）。**

## 六、它到底是怎么"说话"的？（生成 = 循环预测）

```
预测"下一个词最可能是谁" → 把预测的词接到句子尾巴
  → 重新算一遍 → 再预测下一个 → 接到尾巴 → ...
```

**聊天 = "预测下一个词"的循环跑了一遍又一遍。**

### 把循环拆成 Prefill / Decode（硬件必读）

```
[Prefill] 用户输入 200 token  →  一次并行算完，填好 KV 缓存
[Decode]  每步只算 1 个新 token → 查缓存 → 再写入缓存 → 重复
```

| | Prefill | Decode |
|---|---|---|
| 并行度 | 高 | 几乎退化成"一步一步" |
| 瓶颈 | 算力 + 带宽 | **带宽 + 缓存容量** |
| 用户体感 | 首字延迟 | 出字速度 tokens/s |

所以：**首字慢** 往往是 Prefill；**出字慢** 往往是 Decode 被 DDR/KV 卡住。  
排查板端 LLM 性能时，先问清在看哪一段。

### 采样：预测出来的是什么

最后一层输出经线性层变成 **词表上的打分（logits）** → softmax 成概率 → 按策略挑一个 token（贪心 / top-p 等）。

这一步在 **CPU** 上很常见：词表几万维，又不是规整大 GEMM，NPU 不一定划算。  
再次印证 02 课："NPU 不包打天下"。

## 七、和 YOLO 部署链的对照（串回阶段四/五）

| | YOLO 检测 | 端侧 LLM |
|---|---|---|
| 输入 | 一帧 640×640 | 一串 token |
| 主力层 | 卷积 / C3 | 注意力 GEMM + MLP |
| 量化 | INT8 PTQ 常见 | INT8 / **W4A16**（RK3576 路线） |
| 输出后处理 | decode 框 + NMS（CPU） | 采样选词（CPU） |
| 板端指标 | FPS、mAP | **首字延迟、tokens/s、上下文长度** |
| 工具 | rknn-toolkit2 | **rknn-llm**（另一条产品线） |

## 八、口诀

- 词袋陷阱：只有内容没有位置 → 加位置标签
- 一块 = 注意力 + 残差 + LN + MLP，叠 N 次
- 残差 = 原稿 + 修改；MLP = 两块大矩阵
- 聊天 = 预测下一个词循环；先分清 Prefill 还是 Decode
