## 一、核心一句话

**CNN 用卷积"看局部"，大模型用注意力"看全局"。** 这就是两代模型的分水岭。
大模型的日常任务只有一个：**预测下一个词**；聊天 = 这个动作的循环。

## 二、先对齐三个词：Token / Embedding / 参数

学大模型最容易在名词上摔跤，先把地基钉死。

### Token：模型眼里的"字块"

模型不直接吃汉字或英文单词，而是把文本切成 **token**（常见几百到几万词表里的一段）。

```
"神经网络"  →  可能切成  ["神经", "网络"]     两个 token
"NPU"      →  可能就是   ["NPU"]              一个 token
```

- **上下文长度**（2k / 32k / 128k…）说的是 **token 数**，不是汉字字数
- 端侧部署时：token 越多，KV 缓存越大、每步生成越慢——和 03 存储课的"缓冲装不下"是同一类问题

### Embedding：查表把词变成向量

```
词表 id  →  查一张巨大的表  →  一串浮点数（如 4096 维）
   37    →                  →  [0.12, -0.88, …, 0.05]
```

这张表也是**训练学出来的权重**（和卷积核一样，不是人手填的）。  
和 CNN 输入对照：图片天生是像素网格；文字要先"翻译成向量"才能进矩阵乘。

### 参数：模型文件里到底存了什么

```
参数 = 所有层的权重张量
     = Embedding 表 + 每层的 Wq/Wk/Wv/Wo + MLP 两层大矩阵 + LN 的 γ/β …
```

| 说法 | 含义 |
|---|---|
| 7B 模型 | 约 70 亿个可学习数字 |
| INT8 部署 | 这些数字大体按 1 字节存 → 约 7GB 量级（还要加激活/KV） |
| 4bit / W4A16 | 权重再压一半以上——RK3576 官方推荐的 LLM 路线之一 |

**推理 = 权重固定，只做前向。** NPU 不做训练，这一点和 YOLO 完全一样。

## 三、模型种类一览

| 处理对象 | 架构 | 代表 | 干的事 |
|---|---|---|---|
| 图片 | **CNN**（卷积神经网络） | VGG、ResNet、**YOLO** | 识别、检测物体 |
| 图片 | ViT（视觉 Transformer） | — | 新趋势，用注意力看图 |
| 文字/序列 | RNN/LSTM（老一代） | — | 处理序列，已被淘汰 |
| 文字/序列 | **Transformer** | GPT、LLaMA、Qwen、DeepSeek | 对话、生成、推理 |
| 生成图片 | 扩散模型 | Stable Diffusion | 文字生成图片 |

开源的权重：图片侧 ResNet、YOLO 全系列；语言侧 LLaMA、Qwen、DeepSeek、Mistral 等均可下载部署。**NPU 上跑的大多是这些。**

## 四、大模型 vs 老一代（YOLO）——物种区别，不是大小区别

| | 老一代（YOLO） | 新一代（大模型） |
|---|---|---|
| 任务 | **专才**：只做检测 | **通才**：对话、写代码、推理、看图 |
| 架构 | 卷积 | 注意力 |
| 规模 | 几百万~几亿参数 | 几十亿~万亿参数 |
| 训练方式 | 人工标注监督 | 海量文字自监督 |
| 输入 | 一张图（一次前向） | 一串 token（可自回归续写） |
| 用在哪 | 摄像头/手机 NPU | 云端 + 手机/PC NPU |

**大模型的"大" = 参数多 + 学的数据多。**  
但对硬件，更关键的差别是：**检测模型一帧出框；语言模型一个 token 一个 token 往外吐**，带宽和缓存压力形态完全不同。

## 五、为什么有这么多架构？

1. **数据形态不同**：图片局部关联强 → CNN；文字相隔很远也互相影响 → 需要"一眼看全"
2. **一代修一代**：RNN 不能并行、健忘 → Transformer 所有词并行、不健忘 → 统治语言任务
3. **同一任务也有权衡**（准 vs 快 vs 省电）→ 衍生不同部署架构（如端侧用 MobileNet / 蒸馏小模型）

### 为什么 RNN 输了（一句话版）

RNN 像**流水线上一个接一个传纸条**：第 20 个词要等前 19 个算完，难并行；信息传远了还会"淡忘"。  
Transformer 把整句话**一次摊开**，任意两词直接做注意力——可以并行，也"记得住"远处。

## 六、效率三件套（端侧部署必背）

### MoE（专家混合）

一堆"小专家" + 一个"路由器"，每个 token 只激活少数专家。

```
输入 → 路由器 → 只挑 2~3 个专家干活，其余睡觉
```

总参数可以巨大（容量大），但**每次只算一小块**（算力可控）。DeepSeek 是代表。  
对 NPU：要注意"激活专家是动态的"，任务列表/负载不像 CNN 那样完全静态。

### 蒸馏（Distillation）

大老师模型 → 小徒弟模型。徒弟模仿老师的**概率分布**（不只答案）。

```
老师: "猫 0.9 / 狗 0.08 / 狐狸 0.02"  →  徒弟学这个软分布
```

结果：小模型保留大部分能力、跑得快 → **塞进手机/板卡 NPU 的主要手段**。

### KV 缓存（本课预告，第 2/3 课展开）

注意力每生成一个新词，都要和历史所有词算相关度。  
若把历史的 **K、V** 存下来，新词只需算自己那一份——用**显存/内存换计算**。  
这是"长上下文又慢又贵"在工程上的第一刀。

## 七、推理时算力花在哪（给 IC 验证的人）

粗分两阶段（细节第 2/3 课）：

| 阶段 | 在干什么 | 计算特点 | 硬件直觉 |
|---|---|---|---|
| **Prefill** | 一次吃完整段 prompt | 大矩阵乘，可并行 | 吃算力、吃带宽 |
| **Decode** | 每次只生成 1 个新 token | 更像"访存为主" | 吃带宽、吃 KV 缓存容量 |

所以端侧 LLM 的账，不能只看 TOPS：

- **TOPS**：Prefill 快不快
- **DDR 带宽**：Decode 每秒能吐几个 token
- **内存容量**：KV 能撑多长上下文

这和 03 第 2 课"算力便宜、带宽贵"是同一句话的 LLM 版。

```
tokens/s ≈ 带宽 / 每步要搬的数据量     （Decode 的粗算，忽略算力项时）
```

RK3576 上跑 rknn-llm，官方 benchmark 给的就是 tokens/s——**先看这个数，再谈 TOPS**。

## 八、现在发展到哪一步

- **多模态**：一个模型同时看懂文字 + 图 + 声音
- **超长上下文**：百万级 token（KV 与注意力近似是工程热点）
- **Agent**：会调用工具、自己上网干活
- **推理型模型**：先想后答（内部还是在续写 token）
- **端侧化**：模型越做越小越省电，下放到手机/PC 的 NPU——**这是 IC/NPU 工程师的主场**

## 九、我学的定位

```
现在进度: 神经元 → 激活 → 全连接 → 卷积 → 池化 → BN = CNN 地基
                                                      ↓
大模型（Transformer/注意力） = 建在地基上的房子（本阶段开始学）
```

**为什么先学 CNN：** 卷积是最直观的"特征提取"样板，而且端侧 NPU 上两代模型都在跑（摄像头跑 CNN/YOLO，手机助手跑蒸馏小模型）。
