# 数电补课 第1课：MAC 的电路本体——乘法器、加法树、饱和

> 学习日期：2026-08（补课线）
> 阶段：08-数电补课（为 02/03 服务）
> 前提：数电基础（组合逻辑、时序、位宽）；已知神经元 = MAC
> 方式：从你熟悉的门级/位宽直觉接到 NPU 数据通路

---

## 一、核心一句

**一个 MAC = 乘法器 + 累加器。NPU 把上万个 MAC 排成阵列，再用加法树/累加链收结果。**
位宽决定面积、功耗、是否溢出——这是「INT8 为什么便宜」的电路版。

---

## 二、整数乘法器：位宽 → 面积

### 2.1 直觉

```
4×4 乘法：部分积少、加法树浅
8×8 乘法：部分积多一截
16×16：树更深、线更长、更慢更耗电
```

经验规律（综合结果的常见量级，非精确定理）：

| 乘法器 | 相对面积 | 相对动态功耗 |
|---|---|---|
| 8×8 INT | 1× | 1× |
| 16×16 INT | ~3–4× | ~3–4× |
| FP32 尾数乘+对阶 | 数倍于 16×16 | 更高 |

所以「同样硅面积，INT8 能多堆好几倍乘法器」不是口号，是乘法树深度问题。

### 2.2 部分积（手算级）

```
  1011   (11)
× 1101   (13)
------
  1011
 0000
1011
1011
------
1000111   (143)
```

每行是一次「与门 + 移位」，再竖着加。**阵列乘法器**就是把这套部分积网络并行摊开；**树形乘法器**用 Wallace/Dadda 压缩深度。

---

## 三、加法器与加法树：点积怎么「加起来」

点积 `w·x` 是一串乘积求和：

```
p0 + p1 + p2 + … + p26     （3×3×3 卷积一次点积）
```

### 3.1 串行累加 vs 树

```
串行：((p0+p1)+p2)+…   延迟长，但省面积
树：  (p0+p1) 与 (p2+p3) 再合并   延迟 ~log2(N)，面积大
```

NPU 阵列里常见：

- **行内**：部分和沿脉动方向流动（权重固定）
- **行末**：进入 INT32 累加寄存器
- **多输入通道**：用加法树在片上收拢

### 3.2 为什么累加器要用 INT32

INT8×INT8 乘积最大约 127×127 ≈ 16k，15 位有符号就够单次乘（-128×-128 = 16384 是例外，需要 16 位）。  
但点积要连加几十上百次：

```
最坏：100 × 16k ≈ 1.6e6   → 仍远小于 INT32 上限 (~2e9)
```

**留出余量防溢出**，这是「位宽分配」而不是随便加宽。验证时要造极端权重/激活把累加链打满。

---

## 四、饱和与舍入：软件/硬件必须一致

### 4.1 两种处理

```
截断 wrap：  127+1 → -128     （模运算，数值跳变，推理里通常禁止）
饱和 sat：   127+1 →  127     （卡在边界，常见）
```

### 4.2 舍入规则

```
round half away / half to even / toward zero
```

量化公式 `q = round(x/s)` 若软件与 RTL 规则不同，**整层输出会系统性偏一点**。  
IC 验证套路：写 C/Python 黄金模型，bit-exact 对齐。

---

## 五、一个 MAC 单元的「验证清单」雏形

| 检查项 | 为什么 |
|---|---|
| 有符号×有符号符号位 | -128×-128 特殊 |
| 乘积位宽 | 8×8→16，再符号扩展进 32 |
| 累加进位链 | 长链是形式验证好目标 |
| 饱和使能 | 与配置寄存器联动 |
| 使能/时钟门控 | 无效 MAC 是否省电、是否泄数 |

---

## 六、口诀

- 位宽↑ → 树深↑ → 面积/功耗/延迟↑
- 点积 = 乘法树 + 加法树/累加链
- 乘完进 INT32，防的是「加」不是「乘」
- 截断跳变，饱和卡住；规则必须与软件一致

**解释 2**：为什么窄位宽乘法器通常更省面积和功耗？

<details>
<summary>答案</summary>
