## 一、核心一句

**算得快不够，要每拍都有数。片上 SRAM + DMA 双缓冲 + 任务控制器，是 NPU 的「供血系统」。**

---

## 二、片上 SRAM：为什么不是「再大一点的 cache」

| | 通用 cache | NPU 片上缓冲 |
|---|---|---|
| 策略 | 硬件自动替换 | **软件/编译器显式排布** |
| 命中 | 尽力而为 | 可分析、可断言 |
| 适合 | 不规则访存 | 规整滑窗/GEMM |

NPU 讨厌「碰运气」，要 **确定性延迟**。所以缓冲更像 scratchpad + DMA，而不是 cache。

### 容量感（RK 量级）

```
每核卷积缓冲 ~百 KB（社区 TRM 转述）
SoC 共享 SRAM ~1MB 级可分配
DDR GB 级但带宽 ~几十 GB/s
```

---

## 三、双缓冲：算一块、搬下一块

```
时间 →
DMA:   [搬 tile0][搬 tile1][搬 tile2]…
阵列:        [算 tile0][算 tile1]…
```

若串行「搬完再算」，利用率会掉一半。  
双缓冲 = 两块 SRAM 轮换，**把访存藏进计算**。验证要点：切换时刻的 fence/同步，写读别名。

---

## 四、流水线级数（直觉）

```
取权重 → 乘 → 加 → 饱和 → 写回
```

- 级数↑：频率可以更高，但填充/排空延迟↑  
- 脉动阵列：数据一拍挪一格，填充期阵列「喂不饱」

小算子/短序列会吃填充亏——这是「大 GEMM 利用率高、零碎算子差」的电路原因。

---

## 五、任务控制器：像微型 sequencer

RKNPU 不是取指 CPU，而是执行 **任务列表**：

```
任务 = 层描述
     = 输入/输出缓冲
     + 量化 scale/zp
     + tiling 参数
     + DMA 描述符
     + 算子类型/核 mask
```

`.rknn` 编译产物 ≈ 这串任务 + 权重。  
驱动只负责：上电、映射、递交、中断回收——**和你验证 PCIe/ DMA 描述符链是同构问题**。

---

## 六、IOMMU / 地址翻译（一句）

多核 NPU + 共享 DDR，设备侧虚拟地址要翻译。  
验证：错误 IOVA、权限、超时、中断丢失。

---

## 七、口诀

- 缓冲要确定性，不靠 cache 碰运气
- 双缓冲：搬算重叠，利用率翻倍的来源之一
- 脉动有填充延迟，大块才划算
- 任务列表驱动；.rknn = 任务包 + 权重

**计算 1**：双缓冲为什么可能提高利用率？

<details>
<summary>答案</summary>

计算 tile 0 时提前搬 tile 1，把访存延迟藏在计算后面。

<summary>答案</summary>

</details>
