> 学习日期：2026-08-17（讲义编写日，自学后待讨论）
> 阶段：02-为何需要NPU
> 前提：已学第1~4课（知道神经网络 = 乘加 + 激活，卷积 = 滑动点积）
> 方式：讲义 + 手算。本课所有数字都要自己动手算一遍

---

## 一、核心一句话

**量化 = 用一个"缩放比例"把浮点数压成整数存；许多端侧 NPU 用整数乘加器算，再按层重新缩放成下一层需要的格式。**
本课程的 RKNN/INT8 路线以“浮点训练、整数推理”为主线，但 RK3576 也支持 FP16 等其他精度。

---

## 二、为什么要降精度

回看第 1 课：神经网络 = 一堆 MAC。MAC 做得**多快、多便宜、多省电**，直接决定处理器好不好。数字的"宽度"决定这一切：

| 类型 | 位数 | 存储量 | 能表示什么 |
|---|---|---|---|
| FP32 | 32 bit（4 字节） | 1× | 训练标准精度，范围大、精度高 |
| FP16 | 16 bit（2 字节） | ÷2 | 训练/推理可用，范围小 |
| INT8 | 8 bit（1 字节） | ÷4 | **-128 ~ +127，共 256 个编码点；对称量化通常只用 -127~127** |
| INT4 | 4 bit（0.5 字节） | ÷8 | -8 ~ +7，只有 16 个台阶 |

降精度同时赚三笔钱：

1. **计算便宜**：乘法器面积/功耗大约随位宽的平方涨。8×8 整数乘法器比 24×24 尾数乘法器小近一个数量级 → 同样面积堆 9 倍多的乘法器。
2. **搬运便宜**：INT8 数据量只有 FP32 的 1/4。阶段三会看到：**NPU 的瓶颈一半在搬运不在计算**，这条比第一条还值钱。
3. **存得便宜**：权重是模型体积的大头，INT8 模型直接缩小 4 倍（RK3588 上的 .rknn 模型普遍就是这么存的）。

代价：编码点有限，会引入误差。量化的全部手艺就是**控制误差、饱和和舍入规则**。

---

## 三、对称量化手算（本课重点，跟着算）

### 规则

```
量化：  q = round( x / s )          x 是浮点权重，q 是 INT8 整数
反量化：x ≈ q × s
缩放：  s = max|x| / 127            让最大的数正好对准 INT8 的满量程 127
```

直觉：INT8 有 256 个编码点；对称量化通常使用 -127~127 的 255 个对称刻度，`s = max|x|/127`。在不截断、按最近刻度取整时，单次量化误差不超过 `s/2`；超出范围时还要单独看饱和行为。

实际工具链里，权重常按输出通道逐通道定 scale（per-channel），激活常整层一个 scale（per-tensor）；具体以 RKNN 转换日志为准。

### 手算例子：量化 4 个卷积核权重

权重 `w = [0.62, -1.28, 0.45, -0.09]`（典型的小浮点权重）。

**第 1 步：算缩放比例**

```
max|w| = 1.28
s = 1.28 / 127 = 0.01008
```

**第 2 步：逐个除以 s，按工具链规定的舍入规则取整**

| 浮点 w | w/s | 量化 q（INT8） | 反量化 q×s | 误差 |
|---|---|---|---|---|
| 0.62 | 61.51 | **62** | 0.6249 | +0.005 |
| -1.28 | -127.0 | **-127** | -1.28 | 0 |
| 0.45 | 44.65 | **45** | 0.4535 | +0.004 |
| -0.09 | -8.93 | **-9** | -0.0907 | -0.001 |

**第 3 步：检查误差上界**

最大误差 ≤ s/2 = 0.005。所有 4 个数的误差确实都没超过。✅

模型权重通常在 ±1 附近晃，s ≈ 0.008~0.01，**单个权重的绝对误差约为 s/2 量级。网络对小扰动有一定容忍度，但精度损失没有固定的“<1%”保证；检测、分割和 LLM 都必须用任务指标实测。

## 四、整数算乘加，比例最后乘一次

量化后，**乘加全在整数域做**，浮点比例只在最后"结算"时用一次：

```
浮点想算：y = w₁x₁ + w₂x₂        （每个数都是小数）
整数实际算：Y = q₁·p₁ + q₂·p₂     （q 是权重的整数，p 是输入的整数）
最后换算：y ≈ Y × (s_w × s_x)     （s_w 权重比例，s_x 输入比例）
```

手算感受一下：设输入 `x = [2.0, 1.5]`，缩放 `s_x = max|x|/127 = 2.0/127 = 0.01575`，量化后 `p = [127, 95]`（1.5/0.01575 = 95.2 ≈ 95）。

```
整数域：Y = 62×127 + (-127)×95 = 7874 - 12065 = -4191
换算：  y ≈ -4191 × (0.01008 × 0.01575) = -4191 × 0.0001588 = -0.665
对照浮点直接算：0.62×2.0 + (-1.28)×1.5 = 1.24 - 1.92 = -0.68
误差 0.015，来源就是两次舍入——量级完全可控。
```

硬件视角：**NPU 里的 MAC 阵列算的主要是 q·p 这种整数乘加**，累加器用 INT32 降低溢出风险。每层算完后通常要做 requantization：按 s_w×s_x/s_y 重新缩放、舍入并饱和到下一层的整数格式；它不能简单理解成“所有比例最后只乘一次”。

## 五、非对称量化：给"全是非负数"的场景加个零点

ReLU 之后激活值全在 0 ~ 正数之间，用对称量化会浪费一侧刻度（非负区间里负数侧用不上）。所以激活值常用**非对称量化**，多一个零点参数 z：

```
量化：  q = round(x / s) + z        z 把浮点的 0 挪到整数格子的对应位置
反量化：x ≈ (q - z) × s
```

例如 x 范围是 [0, 2.54]，取 s = 2.54/255、z = 0，量化范围约是 0~255（实际端点由工具链的 scale/zero-point 约定决定）。z 不一定为 0，本例只是为了先看缩放；真正的零点示例应满足 x=0 映射到整数 z。

再补一个 z≠0 的：x ∈ [-1, 3]，s = 4/255 ≈ 0.0157，z = round(1/s) ≈ 64；于是 x=0 → q=64、x=-1 → q=0、x=3 → q=255。

口诀：**对称管"两边晃"（权重），非对称管"一边倒"（激活）**。RKNN 工具链会自动决定每层用哪种（模型转换日志里能看到 `asymmetric_quantized-8` 之类的字样）。

## 六、误差从哪来、怎么救（对上工具链）

量化不是拍脑袋定 s，而是**用数据"校准"（calibration）**：拿几百张真实输入图跑一遍浮点网络，统计每层数值的实际范围，再定每层的 s。这就是训练后量化 PTQ——不用重新训练，几分钟搞定。

精度不够时的救援阶梯（RKNN-Toolkit2 都有对应工具，阶段四实操）：

1. **换校准数据**：校准集不代表性 → 范围定错 → 换数据重跑（最常见）
2. **精度分析**：`accuracy_analysis` 逐层对比量化前后的输出（余弦距离），**找出是哪一层掉的精度**
3. **混合量化**：把精度敏感的少数层保持 FP16，其余 INT8（RK3576/RK3588 支持 FP16 才有此选项；RK3566/3568 只能 INT8/INT16）
4. **量化感知训练 QAT**：训练时就"模拟量化"，让权重学会适应整数格子（要训练资源，端侧部署一般用不上）

## 七、加深：把「格子」和电路接上（补数电）

### 8.1 为什么偏偏是 127 不是 128

INT8 有符号范围 −128~+127，**正数只有 127**。对称量化用 `s = max|w|/127`，让最大正值对准 +127。  
若误用 128，正端会系统性缩一点——软件/硬件/工具链三处必须同一约定。

### 8.2 量化误差是「舍入噪声」不是随机噪声

```
|x̂ - x| ≤ s/2
```

是**确定性上界**。所以：

- 可以写断言：任意输出 |Δ| ≤ s/2（同层）  
- 多层误差会累积/相关，不能简单「每层 1% 总共还是 1%」  
- 校准集决定 s；s 错了，整层一起错

### 8.3 和乘法器位宽的对话

```
INT8×INT8 → 乘积约 16 bit
点积累加 → INT32
requantize：按 s_w×s_x/s_y 缩放、舍入、饱和到下一层格式
```

对应数电课：乘法树不宽，累加器很宽。  
**验证乘法器时测 8×8；验证系统时测长累加链。**

### 8.4 W4A16 是什么（RK3576 独门）

```
W4  = 权重 4bit（格子更粗，模型更小）
A16 = 激活 FP16（动态范围保一点）
```

LLM 权重巨大、激活范围更飘——所以权重狠压、激活留 FP16。  
这是「按张量角色选位宽」，不是全局一刀切。

## 八、加深：校准到底在干什么

```
1. 拿 100~300 张「像真实输入」的样本
2. 跑浮点网络，记录每层输出 min/max 或分位数
3. 用统计定 s（以及非对称的 z）
4. 写入 .rknn 的量化参数
```

| 校准集问题 | 现象 |
|---|---|
| 太窄（全白天图） | 夜间图激活溢出/饱和，mAP 掉 |
| 太脏/离群 | s 被撑大，正常值全部挤进少数格子 |
| 任务不匹配 | 检测模型用分类数据校准 |

工具链 `accuracy_analysis` 就是在回答：**哪一层的量化把信息弄丢了。**

## 九、IC 验证视角

如果量化单元/MAC 阵列交给你测，关注点：

- **饱和与溢出**：量化公式若 max 定错，round 后超 ±127 → 截断还是饱和？累加器 INT32 连加多少次会溢出？
- **舍入规则**：round 是四舍五入、向零取整还是 banker's rounding？软件模型和硬件实现必须逐 bit 一致，否则精度对不上
- **缩放常数**：s 是逐层甚至逐通道的，配置通路（寄存器/DMA 搬运）传错一层，全图悄悄错
- 量化本身是纯数学，**最好先写一个 C/Python 黄金模型**，硬件输出和它对——这正是你熟悉的验证套路

## 十、口诀

- 浮点训练、整数推理
- 127 对满量程，除 s 四舍五入；误差不过半格（s/2）
- 对称管权重、非对称管激活（多一个零点 z）
- 算在整数、比例最后乘
