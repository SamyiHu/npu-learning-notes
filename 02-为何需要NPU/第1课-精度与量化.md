## 一、核心一句话

**量化 = 用一个"缩放比例"把浮点数压成整数存；NPU 用整数乘加器算，算完再乘回比例。**
浮点训练、整数推理——这是 NPU 又快又省电的第一根支柱（第二根是架构，下课讲）。

---

## 二、为什么要降精度

回看第 1 课：神经网络 = 一堆 MAC。MAC 做得**多快、多便宜、多省电**，直接决定处理器好不好。数字的"宽度"决定这一切：

| 类型 | 位数 | 存储量 | 能表示什么 |
|---|---|---|---|
| FP32 | 32 bit（4 字节） | 1× | 训练标准精度，范围大、精度高 |
| FP16 | 16 bit（2 字节） | ÷2 | 训练/推理可用，范围小 |
| INT8 | 8 bit（1 字节） | ÷4 | **-128 ~ +127，共 256 个台阶** |
| INT4 | 4 bit（0.5 字节） | ÷8 | -8 ~ +7，只有 16 个台阶 |

降精度同时赚三笔钱：

1. **计算便宜**：乘法器面积/功耗大约随位宽的平方涨。8×8 整数乘法器比 24×24 尾数乘法器小近一个数量级 → 同样面积堆 9 倍多的乘法器。
2. **搬运便宜**：INT8 数据量只有 FP32 的 1/4。阶段三会看到：**NPU 的瓶颈一半在搬运不在计算**，这条比第一条还值钱。
3. **存得便宜**：权重是模型体积的大头，INT8 模型直接缩小 4 倍（RK3588 上的 .rknn 模型普遍就是这么存的）。

代价：数字只有 256 个台阶，会引入误差。量化的全部手艺就是**控制这个误差**。

## 三、对称量化手算（本课重点，跟着算）

### 规则

```
量化：  q = round( x / s )          x 是浮点权重，q 是 INT8 整数
反量化：x ≈ q × s
缩放：  s = max|x| / 127            让最大的数正好对准 INT8 的满量程 127
```

直觉：INT8 只有 -128~+127 这 256 个"格子"，量化就是**把浮点范围等分成 256 格，每格宽度就是 s**。误差最大不会超过半格（s/2）。

### 手算例子：量化 4 个卷积核权重

权重 `w = [0.62, -1.28, 0.45, -0.09]`（典型的小浮点权重）。

**第 1 步：算缩放比例**

```
max|w| = 1.28
s = 1.28 / 127 = 0.01008
```

**第 2 步：逐个除以 s，四舍五入**

| 浮点 w | w/s | 量化 q（INT8） | 反量化 q×s | 误差 |
|---|---|---|---|---|
| 0.62 | 61.51 | **62** | 0.6249 | +0.005 |
| -1.28 | -127.0 | **-127** | -1.28 | 0 |
| 0.45 | 44.65 | **45** | 0.4535 | +0.004 |
| -0.09 | -8.93 | **-9** | -0.0907 | -0.001 |

**第 3 步：检查误差上界**

最大误差 ≤ s/2 = 0.005。所有 4 个数的误差确实都没超过。✅

模型权重通常在 ±1 附近晃，s ≈ 0.008~0.01，**每个权重的绝对误差约千分之五**。神经网络对这种小扰动天然不敏感（训练时权重本来就在抖），所以 INT8 推理精度损失通常 <1%——这就是量化敢用的底气。

## 四、整数算乘加，比例最后乘一次

量化后，**乘加全在整数域做**，浮点比例只在最后"结算"时用一次：

```
浮点想算：y = w₁x₁ + w₂x₂        （每个数都是小数）
整数实际算：Y = q₁·p₁ + q₂·p₂     （q 是权重的整数，p 是输入的整数）
最后换算：y ≈ Y × (s_w × s_x)     （s_w 权重比例，s_x 输入比例）
```

手算感受一下：设输入 `x = [2.0, 1.5]`，缩放 `s_x = max|x|/127 = 2.0/127 = 0.01575`，量化后 `p = [127, 95]`（1.5/0.01575 = 95.2 ≈ 95）。

```
整数域：Y = 62×127 + (-127)×95 = 7874 - 12065 = -4191
换算：  y ≈ -4191 × (0.01008 × 0.01575) = -4191 × 0.0001588 = -0.665
对照浮点直接算：0.62×2.0 + (-1.28)×1.5 = 1.24 - 1.92 = -0.68
误差 0.015，来源就是两次舍入——量级完全可控。
```

硬件视角：**NPU 里的 MAC 阵列算的全是 q·p 这种整数乘加**，累加器宽一点（INT32）保证不溢出；每层的 s_w×s_x 是一个已知常数，可以折进下一层或者最后统一乘。这就是"NPU 用 INT8 算"的完整含义。

## 五、非对称量化：给"全是非负数"的场景加个零点

ReLU 之后激活值全在 0 ~ 正数之间，用对称量化浪费一半格子（-128~-1 永远用不上）。所以激活值常用**非对称量化**，多一个零点参数 z：

```
量化：q = round(x / s) + z        z 把浮点的 0 挪到整数格子的对应位置
```

例如 x 范围是 [0, 2.54]：s = 2.54/255 = 0.01，z = 0，用满 0~255（UINT8，正好一个字节）。

口诀：**对称管"两边晃"（权重），非对称管"一边倒"（激活）**。RKNN 工具链会自动决定每层用哪种（模型转换日志里能看到 `asymmetric_quantized-8` 之类的字样）。

## 六、误差从哪来、怎么救（对上工具链）

量化不是拍脑袋定 s，而是**用数据"校准"（calibration）**：拿几百张真实输入图跑一遍浮点网络，统计每层数值的实际范围，再定每层的 s。这就是训练后量化 PTQ——不用重新训练，几分钟搞定。

精度不够时的救援阶梯（RKNN-Toolkit2 都有对应工具，阶段四实操）：

1. **换校准数据**：校准集不代表性 → 范围定错 → 换数据重跑（最常见）
2. **精度分析**：`accuracy_analysis` 逐层对比量化前后的输出（余弦距离），**找出是哪一层掉的精度**
3. **混合量化**：把精度敏感的少数层保持 FP16，其余 INT8（RK3576/RK3588 支持 FP16 才有此选项；RK3566/3568 只能 INT8/INT16）
4. **量化感知训练 QAT**：训练时就"模拟量化"，让权重学会适应整数格子（要训练资源，端侧部署一般用不上）

## 七、IC 验证视角

如果量化单元/MAC 阵列交给你测，关注点：

- **饱和与溢出**：量化公式若 max 定错，round 后超 ±127 → 截断还是饱和？累加器 INT32 连加多少次会溢出？
- **舍入规则**：round 是四舍五入、向零取整还是 banker's rounding？软件模型和硬件实现必须逐 bit 一致，否则精度对不上
- **缩放常数**：s 是逐层甚至逐通道的，配置通路（寄存器/DMA 搬运）传错一层，全图悄悄错
- 量化本身是纯数学，**最好先写一个 C/Python 黄金模型**，硬件输出和它对——这正是你熟悉的验证套路
