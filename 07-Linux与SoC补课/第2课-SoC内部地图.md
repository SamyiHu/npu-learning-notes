## 一、核心一句话

**SoC = 一座城市：CPU 集群是政务区，NPU/GPU/VPU 等是各有绝活的专业工厂，互连总线（NOC/AXI）是路网，DDR 是全城唯一的公共仓库。**
城市好不好，不取决于某个工厂多强，而取决于**路网会不会堵**——这正是 NPU 课程反复强调带宽的原因。

（CPU 配置注：官方数据手册写 A76 "up to 2.4GHz"；"1×2.4 + 3×2.2" 是社区广泛引用的说法，了解即可。）

### 每个 IP 和 NPU 的关系（挑相关的记）

| 街区 | 一句话职责 | 与 NPU 的关系 |
|---|---|---|
| CPU A76/A55 | 跑系统、跑你的应用和后处理 | 应用经 librknnrt 指挥 NPU；不支持的算子回退到它 |
| GPU | 3D/图形，也能跑推理但不划算 | 和 NPU 抢 DDR 带宽的邻居 |
| VPU | 视频硬编解码 | 视频流 AI 的第一棒：解码出的帧喂给 NPU |
| ISP | 摄像头原始数据处理 | 摄像头 AI 的第零棒 |
| RGA | 2D 图像加速（缩放/色转） | NPU 的专职前处理（04 第 2 课） |
| VOP | 显示输出 | "检测框画到屏幕上"那一棒 |
| IOMMU | 给没有 MMU 的 IP 做地址翻译 | NPU 三个核共享一个 IOMMU（03 第 3 课） |
| DMAC | 搬数专家 | 各 IP 缓冲进出的通道 |

**完整 AI 流水线就是一次跨城接力**：ISP/摄像头 → RGA → NPU → CPU 后处理 → VOP 显示，每一棒都进城仓库（DDR）取放货。

## 三、MCU 对照：三认知升级

### 1. 从"单主设备"到"多主设备"

MCU：CPU 是唯一总线主，外设全是从。SoC：CPU 各核、GPU、NPU、VPU、DMAC **都是主设备**，同时发起访问，总线矩阵要**仲裁**（谁先谁后、QoS 优先级）。→ 这就是总线仲裁/带宽争用问题的物理来源，也是你 SoC 级验证工作的主战场。

### 2. 从"物理地址直通"到"两级翻译"

- CPU 侧：虚拟地址 →（MMU）→ 物理地址，你熟
- 设备侧：NPU 看到的"设备地址" →（**IOMMU**）→ 物理地址。好处：不连续的物理内存拼成连续视图、地址隔离防外设越界
- NPU 驱动递交任务前必须先建 IOMMU 页表——03 第 3 课"驱动映射缓冲"指的就是这件事

### 3. 从"私有外设"到"公共仓库"

MCU 的 SRAM 各外设多半独享。SoC 里**唯一的大仓库 DDR 是全城共享的**：阶段三算过，NPU 一层卷积写 3.2MB、摄像头 4K 视频 ~373MB/s、VPU 解码再翻几倍……都在 ~34GB/s 的门口排队。带宽预算表（bandwidth budget）是 SoC 架构师的日课——你现在会算 NPU 这一份了。

手算感受公共仓库的拥挤（延续 03 第 2 课）：

```
1080p30 NV12 摄像头流      ≈ 93 MB/s   （1920×1080×1.5B×30）
同一画面 RGA 读+写          ≈ 186 MB/s
NPU 每帧 30 层平均各读写    ≈ 每帧几十 MB × 30fps ≈ GB/s 级
显示输出再读一份            ≈ 93 MB/s
→ 单路视频 AI 轻松吃掉几 GB/s；多路并发（NVR 场景）带宽就成了第一瓶颈
```

## 四、地址地图与 MMIO（你早已会的技能，换个名字）

SoC 里每个 IP 的寄存器仍占一段**物理地址**（memory-mapped I/O），如 NPU 三核寄存器区在 `0xfdab0000/0xfdac0000/0xfdad0000`。MCU 里你写 `*(volatile u32*)ADDR` 直接摸；Linux 里这段被内核驱动独占，用户态只能通过驱动接口操作——**地址没变，只是"摸的方式"被操作系统管起来了**（呼应第 1 课租户思维）。

---

## 五、时钟与电源域（能效的另一只手）

- 每个 IP 有自己的时钟树（NPU 有 ACLK/HCLK）和**电源域**（RK3588 里 npu0/1/2 各自独立可控电）
- Linux 的 devfreq/cpufreq 按负载动态调频调压（DVFS）——NPU 空闲降频、忙时拉满，`/sys/kernel/debug/rknpu/freq` 可看
- 对上 IC 视角：你验证过的 clock gating、power isolation、reset 序列，正是这些软件机制能成立的地基；运行中调频调压的数据完整性，也是 03 第 3 课验证清单的条目

---

## 六、IC 验证视角

SoC 级 = 你当前职业的主场，这里只画一条线把 NPU 课程接上：

```
IP 级验证（MAC 阵列/DMA 单元）
   → 子系统级（NPU 三核 + IOMMU + 缓冲管理）
      → SoC 级（总线仲裁/QoS、与 VPU/GPU 并发的带宽、电源域交互）
         → 系统级（真实负载：跑 YOLO 的同时解码 4 路 1080p——压测场景就是产品场景）
```

NPU 验证工程师的价值差就在后两级：会构造"真实 AI 负载 + 邻居并发"的激励。你补这套课的终点，就是能设计这种场景。
