## 一、核心一句话

**算力便宜，带宽贵。MAC 阵列每秒能吃几个 TB 的数据，DDR 每秒只给几十 GB——NPU 设计一半以上功夫花在"别让数据跑远路"上。**

---

## 二、存储金字塔（RK3588 实际数字）

```
        快 ←──────────────────────────────→ 慢
        贵（每字节）                    便宜（每字节）

 MAC 阵列内累加器     每核片上缓冲        SoC 共享 SRAM        外部 DDR
 （INT32 寄存器）    （~百 KB 量级*）     （共 1MB，可分配）    （GB 级）
  纳秒级、随取        核私有、DMA 喂      各 IP 可申请          LPDDR4X 64bit
                                                          ≈ 34 GB/s 理论（推算）
```

\* RK3588 每核片上存储约 384KB（含卷积缓冲），来自 TRM 的社区逆向资料，精确数字待确认。SoC 级：RK3588 内部有 1MB SRAM，其中 956KB 可分配给各 IP（含 NPU），这是官方 RKNPU User Guide 写明的——把常用权重/特征图放这里，可以显著减少 DDR 流量。

关键数量级感受：

| 存储层 | 容量 | 带宽量级 |
|---|---|---|
| 每核片上缓冲 | ~384 KB | 内部通路，TB/s 级 |
| SoC SRAM | 1 MB | 高，但容量小 |
| DDR (LPDDR4X ×64bit) | 4~32 GB | **~34 GB/s 理论，实测打折** |

**DDR 比片上缓冲慢约两个数量级**。而一个 YOLO 模型的权重就有 ~7MB（INT8），根本住不进片上——必须来回搬。怎么少搬、巧搬，就是本课全部内容。

## 三、手算：一层卷积的"搬运账"（继续用老朋友）

第 2 课的层：输入 224×224×3，64 核 3×3，输出 224×224×64。计算量 0.17 GOP。

```
INT8 数据量：
  输入   = 224×224×3  = 150 KB
  权重   = 64×3×3×3   = 1.7 KB
  输出   = 224×224×64 = 3.2 MB
```

### 情形 A：傻算——每层都经 DDR

```
NPU 单核算力 2 TOPS → 计算时间 = 0.17 GOP / 2 TOPS ≈ 87 µs

DDR 搬运量 ≈ 读输入 150KB + 读权重 1.7KB + 写输出 3.2MB ≈ 3.4 MB
DDR 带宽 34 GB/s → 搬运时间 = 3.4 MB / 34 GB/s = 100 µs

瓶颈 = max(计算 87µs, 搬运 100µs) = 100 µs ← 被搬运卡住！
```

**写回输出一项（3.2MB → 95µs）就比计算还慢。** 而且这还是整个网络 50+ 层里的一层，每层都来一趟"DDR 写入→下一层再读出"，DDR 流量翻倍，还和 CPU/GPU/视频抢带宽（DDR 是全 SoC 公共仓库，07 补课线细讲）。

### 情形 B：聪明算——输出留在片上直接喂下一层

```
输出 3.2MB 住片上（384KB 放不下整张？→ 分块，见下节）
下一层直接从片上读 → DDR 流量只剩"必须进出的部分"
搬运时间大幅下降，瓶颈回到计算 ~87 µs
```

这就是**层间融合/片上级联**：输出不回 DDR，在片上缓冲里直接变成下一层的输入。多少层能连着融，取决于片上缓冲多大——所以**片上 SRAM 大小是 NPU 的核心规格**（和 MAC 数并列）。

### 运算强度：一句话判断瓶颈在哪

```
运算强度 = 计算量 / 数据量    （ops/byte）
  普通卷积：0.17 GOP / 3.4 MB ≈ 50 ops/byte   → 高，倾向计算瓶颈
  逐通道卷积(depthwise)、元素级操作(加/拼接)：几乎每字节只配一两次运算 → 低，纯搬运瓶颈
```

深层网络里浅层大卷积是"算得多"，深层 1×1、depthwise、残差相加是"搬得多"。**NPU 的编译器（工具链）花大量精力决定每层的切分和排布**，这也是后面工具链课的伏笔。

## 四、分块（Tiling）：大任务怎么塞进小缓冲

特征图 3.2MB > 缓冲 384KB，装不下怎么办？——切：

```
把输出特征图按 H 方向切成条（tile），每条约 300KB：
  for 每条输出:
      DMA 把这条需要的输入行、权重搬进来
      阵列算完这条 → 结果直接给下一层用，或写回 DDR
```

切分粒度是编译器的优化空间：太大装不下，太小则"边界数据反复搬"（滑动窗口重叠区）。这套思想和 cache 分块优化、你熟悉的 DMA 描述符链完全同源。

**权重通常整个常驻片上**（几 MB 量级按层轮换），因为权重复用率最高、且层内不变。

## 五、把 DDR 流量当预算花（SoC 视角，预告 07 补课线）

RK3588 上跑一个"摄像头→检测"应用，DDR 带宽 (~34GB/s 理论) 是所有 IP 共享的：

```
摄像头采集 → VPU 编解码 → RGA 缩放/色转 → NPU 推理 → CPU 后处理 → 显示
      └────────────── 每一环都要读写 DDR，全走同一个仓库门 ──────────────┘
```

优化思路两条：

1. **少搬**：层间融合、SRAM 放权重、INT8（数据量直接 ÷4）
2. **别重复搬**：**零拷贝（zero-copy）**——摄像头缓冲、RGA 输出、NPU 输入如果各拷一份，DDR 流量 ×3。Linux 的 dma-buf 机制让各家 IP 共享同一块物理内存（只传"句柄"不传数据）。RKNN 的 `rknn_create_mem_from_fd()`、RGA 的 `importbuffer_fd()` 都是为这条链路准备的（阶段四见真身）

## 六、IC 验证视角

存储/搬运是 NPU 验证的重灾区：

- **DMA 引擎**：描述符边界（跨页、未对齐）、outstanding 数、和 IOMMU 配合的地址翻译错误
- **缓冲管理**：tile 边界读写越界、ping-pong 缓冲切换时的竞态（上一块还没读完就开写下一块）
- **一致性**：CPU 改过的数据 NPU 要看到（cache 维护/一致性域），漏 flush 就是"偶现错数"——最难查的一类 bug
- **带宽/QoS**：多主设备抢 DDR 时的死锁/饿死（SoC 级验证话题，正是你的主场）

---

## 七、口诀

- 算力便宜、带宽贵；DDR 慢片上两个量级
- 判断瓶颈看运算强度（ops/byte）：高算瓶颈、低搬瓶颈
- 装不下就切块（tile），权重常驻、激活流动
- 能不搬就不搬（融合），必须搬就共享（零拷贝）
