## 一、核心一句话

**NPU 核心 = 一大片 MAC 阵列（算）+ 片上缓冲（存）+ DMA（搬）+ 固定功能小单元（激活/池化）+ 一个任务控制器（指挥）。**
设计 NPU 的全部艺术 = 让上千个乘法器每拍都有数据可吃。

---

## 二、MAC 阵列：从 1 个到 1024 个

第 1 课学过：神经元 = 1 个 MAC。NPU 就是把 MAC **排成方阵**：

```
1 个 MAC   =  1 乘 + 1 加，每拍 1 个

32×32 阵列 = 1024 个 MAC 同时干活，每拍 1024 个乘加 = 2048 ops
```

### 手算：RKNPU 一核的算力从哪来

RK3588 NPU 每核：**1024 个 INT8 MAC/拍**（来自 TRM 的社区转述，逆向博客核对过），频率约 1 GHz（推算）：

```
1024 MAC/拍 × 2 ops × 10⁹ 拍/s = 2.048 × 10¹² ops/s ≈ 2 TOPS
```

这就是"每核 2 TOPS"的全部秘密——没有魔法，只有**乘法器数量 × 频率**。三核并排，6 TOPS。（对照第 2 课的手算，数字能对上。）

### 阵列怎么吃卷积

回想卷积的循环结构：

```
for 每个输出通道 Co:        ← 64 个核
  for 每个输出位置 (i,j):   ← 50176 个位置
    for 每个输入通道+核内:   ← 27 次乘加
```

四层循环里藏着**复用**：同一个核的 9 个权重，被 50176 个位置重复用；同一个输入像素，被 64 个核重复用。阵列就是**把循环摊开成空间**：

- 一行 MAC 吃同一个输出位置的 27 次乘加（部分和沿行累加）
- 64 行并行吃 64 个核
- 输入数据从缓冲里"流"过阵列，流过的每一拍都在被不同的行使用

**利用率**：阵列 1024 格，哪拍没喂满哪拍浪费。真实模型利用率 30~60%（第 2 课的折扣就在这），取决于层的形状凑不凑得满 32 的倍数、通道数够不够铺满。

## 三、数据流：权重、输入、输出谁"住"在阵列边上

上千 MAC 并行，每拍要喂 1024 份数据——不可能每个 MAC 自己去内存取。三种经典排法（学术界叫 dataflow）：

### 1. 权重固定（Weight Stationary）

权重一次载入就"住"在 MAC 里不动，输入数据流过，部分和流出去。

```
优点：权重只读一次，复用率最高（权重最金贵——每个权重要用几万次）
缺点：部分和要在阵列间流动/累加，互连压力大
典型：多数端侧 NPU（含 RKNPU 这类）以此为主
```

### 2. 输出固定（Output Stationary）

每个 MAC（或每行）负责一个固定输出的完整累加，算完才交出去。

```
优点：部分和不出阵列，累加不占外部带宽
缺点：权重和输入都要反复广播/搬运
```

### 3. 行固定（Row Stationary，MIT Eyeriss 提出）

把卷积按"行"切给每行 MAC，三类数据都有复用。

```
优点：总能耗最优（学术上）
代价：控制最复杂
```

**不必背细节，记住结论：数据流的选择 = 决定"谁少跑路"。** 不同层（大核/小核、通道多/少）适合不同流法，商用 NPU 常混合使用。

### 脉动阵列（Systolic Array）：让数据"像血液一样流动"

Google TPU 的经典结构，值得认识（面试常客）：

```
传统广播式：数据从缓存"广播"给所有 MAC → 线多、扇出大、频率上不去
脉动式：    数据只传给相邻的 MAC，一拍一拍往前"挤"，像心脏泵血
            每拍进入一个新数据，阵列里同时流着好几个数据，各自在不同阶段被用
```

优点：互连极短（只连邻居）→ 高频、省电；缺点：数据要提前"排好队"进入，填充/排空有延迟，适合大矩阵不适合零碎小算子。

## 四、MAC 阵列之外的固定功能单元

NPU 不是只有乘加阵列。围绕阵列一圈"小硬件"，各干一件事：

```
┌─────────────────────────────────────────────┐
│                 NPU 核心内部                  │
│                                             │
│   权重缓冲 ──┐                               │
│   激活缓冲 ──┼──→  MAC 阵列 32×32  ──→ 累加器组（INT32）│
│   (片上SRAM) ┘         │                     │
│                       ↓                     │
│              激活单元(ReLU等,比较器实现)       │
│                       ↓                     │
│              池化单元(最大/平均,固定逻辑)       │
│                       ↓                     │
│              量化/反量化单元(乘s、舍入)        │
│                                             │
│   DMA ←→ 片上缓冲 ←→ 外部 DDR                │
│   任务控制器: 逐条执行"任务列表"               │
└─────────────────────────────────────────────┘
```

对照已学知识：

- **激活函数**（第 1 课）：ReLU 硬件 = 一个比较器+选择器，几乎白送
- **池化**（第 3 课）：无权重、固定规则 → 纯组合逻辑小单元
- **BN**（第 3 课）：推理时折叠成两个乘加 → 直接融进卷积的输出通路，**硬件里根本没有"BN 单元"**
- **量化/反量化**（阶段二）：乘 s + 舍入，也是小乘法器+舍入逻辑

这就是"固定功能"的含义：**每种算子一小块专用电路**，而不是 CPU 那样的通用指令执行。支持的算子列表 = 硬件电路清单，列表外的算子只能 CPU 执行（呼应第 2 课"NPU 不包打天下"）。

## 五、卷积怎么变成矩阵乘（im2col + 数据排布）

阶段一说过"卷积本质是线性变换"。NPU 实现时普遍用 **im2col** 思路：把每个滑动窗口的像素复制排成矩阵的一行/列，卷积就变成标准 GEMM，直接喂 MAC 阵列。

代价是数据重排/复制——这正是 NPU 内部缓冲和 DMA 的日常工作之一。RKNPU 用的 5 维排布 **NC1HWC2**（C2=16，即通道按 16 个一组打包）就是为 MAC 阵列的宽度量身定做的：通道 16 个一组进阵列，正好铺满一排处理单元（逆向社区资料）。你不需要记格式细节，但要记住：**模型里张量的"形状"到硬件里会变成"搬运和排布方案"，排布是 NPU 编译器（RKNN 工具链）最重要的工作之一**。

## 六、IC 验证视角

MAC 阵列是规整结构，验证抓手：

- **单元级**：单 MAC 的乘法+累加+饱和/溢出，可用形式验证全查
- **阵列级**：上千 MAC 的累加链一致性——随机注入一个错，能否被检测？（奇偶/ECC 设计有没有）
- **数据流级**：激励要像真实模型（权重量化后的分布、滑窗地址序列），纯随机激不出排布冲突
- **控制级**：任务列表的切换、阵列的填充/排空、异常打断后状态是否干净
